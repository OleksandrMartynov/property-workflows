# UX усієї системи: аудит і план (WS8)

Мета — зробити роботу зручною для всіх ролей зараз і закласти місце для наступних зрізів roadmap PM (WS9 — змінні й
умови запуску, WS10 — AI-розбір документів, WS11 — сторінка статусу за посиланням), не реалізуючи їх наперед.
Межі: тексти з AC PM — дослівно; правила `DESIGN.md` (лише токени й компоненти `src/components/ui`, без пояснювального
тексту, статус — іконка + слово, незворотна дія — `ConfirmDialog`); локатори тестів і UAT (`tests/**`) не ламаємо.

## Інформаційна архітектура

- Навігація без нових пунктів: admin і manager — Home · Templates · Runs; vendor — лише Runs.
- «Мої задачі» — вигляд списку запусків (`Segmented`: All · Mine · In progress · Completed), не окрема сторінка; для
  vendor увесь список і є «мої», перемикача немає. Порядок «новіші першими» (AC-TASK-14) — без змін.
- Пошук: рядок над списком (`?q=` за назвою випадку, серверно) і ⌘K для всього застосунку.
- Нагадування замість листів (поза scope PM — листи): число відкритих моїх задач біля Runs і позначка «Assigned to you»
  у рядку запуску.
- WS9: блок «Answers» над чеклістом; задачі, сховані умовою, — один рядок-підсумок (`Badge variant="variable"`);
  зміна відповіді, що скидає кроки, — через `ConfirmDialog`; у редакторі умова — в інспекторі задачі (`DetailPanel`).
- WS10: поле з пропозицією AI (`Badge variant="ai"`) і діями Accept / Edit / Reject; документ — у `DetailPanel` поруч;
  значення не зберігається без підтвердження.
- WS11: окремий маршрут поза `(app)` з мінімальним каркасом без навігації: статус, прогрес «N of M done»; у запуску —
  «Copy status link» / «Revoke link» (через `ConfirmDialog`), шлях — у `public-paths.ts`.
- Вибір виконавця — лише email (AC-RUN-10, AC-VENDOR-02): без груп за роллю й бейджів ролей.

## Партії (по PR)

1. Каркас: акаунт, тема й пошук на телефоні; помилки й «не знайдено» в каркасі; скелети; `back` на формі запуску.
2. Відгук на дії: `FlashNotice`, оптимістичне «Mark as done», помилка біля поля назви випадку.
3. Список запусків: вигляди й пошук, телефон, лічильники головної ведуть на вигляди.
4. Сторінка запуску без шуму: прогрес і статус, «N of M done» у секціях, свої задачі, `DetailPanel`.
5. ⌘K-пошук запусків і шаблонів, `/`, нагадування.
6. Форма запуску й редактор під WS9–WS10: один «Who does what», одна кнопка Launch, слот «Answers», інспектор задачі.

Нові підписи, яких немає в AC (напр. «No runs found.», «Mine»), — лише назви й стани, без пояснювального тексту;
поведінку WS9–WS11 не реалізуємо до вимог PM.
