# 0001. Запуск зберігає копію задач шаблону

- Статус: прийнято
- Дата: 2026-10-19
- AC: AC-RUN-01, AC-RUN-02, AC-RUN-04, AC-RUN-08, AC-RUN-09

## Контекст

Запуск має містити всі задачі шаблону (AC-RUN-01), а пізніші зміни шаблону адміністратором — додана задача,
перейменування — не повинні змінювати вже створений запуск (AC-RUN-02). Кожна задача запуску має рівно одного
виконавця (глосарій PM, «Assignee»). Кілька запусків одного шаблону йдуть одночасно, кожен зі своїми виконавцями.

## Рішення

- `runs` і `run_tasks` — окремі таблиці. Функція `launch_run` однією транзакцією створює запуск і **копіює** в
  `run_tasks` назву, секцію, порядок і позначку `required` кожної задачі шаблону, а також ставить виконавця.
- `run_tasks.template_task_id` — лише довідка, звідки скопійовано, без зовнішнього ключа: шаблон можна змінити чи
  видалити, запуск від цього не залежить. `runs.template_name` — теж копія.
- Запис у `runs` / `run_tasks` для клієнта закрито (лише `select`); пише тільки функція `private.launch_run`
  (`security definer`, `search_path = ''`) через обгортку `public.launch_run`.

## Розглянуті варіанти

- Посилання `run_tasks → template_tasks` без копії — перейменування задачі шаблону змінило б назву в усіх запусках
  (порушує AC-RUN-02).
- Версії шаблону (незмінні рядки `template_versions`) — теж виконує AC-RUN-02, але складніше: потрібні правила
  створення версій і екран, якого в зрізі немає. Копія простіша і дає те саме.
- Запис запуску й задач з server action кількома запитами supabase-js — без транзакції, тож при збої лишився б запуск
  без частини задач.

## Наслідки

- Зміни шаблону після запуску не видно в запуску — так і задумано. Якщо PM захоче «оновити запуск до нової версії
  шаблону», це буде окрема дія.
- Дублювання назв задач у кожному запуску — прийнятне для обсягів агенції.
