# Пропозиція: редактор шаблону з версіями і єдина дизайн-система (зріз 2, WS7)

## Why

Адміністратор не може змінити шаблон у застосунку: кожна зміна означає підготовку даних поза ним, і ніхто не знає, за
якою версією процесу йде запуск. Після цього зрізу адміністратор редагує шаблон і зберігає його як пронумеровану
версію; доти зміни зберігаються, але менеджери працюють з останньою збереженою версією. Адміністратор бачить список
версій, а вже запущені запуски не змінюються й показують свою версію. Окремо: сторінки, зроблені по одній, виглядають
і поводяться по-різному; після зрізу кожна сторінка однаково показує статуси, порожні списки й відмови в доступі.

## What Changes

`template-editor` (нова можливість):

- ADDED «Незбережені зміни шаблону»: зміни в редакторі зберігаються самі, а шаблон показує «Unpublished changes»
  (AC-EDITOR-01).
- ADDED «Менеджер бачить лише поточну версію»: незбережених змін менеджер не бачить (AC-EDITOR-02).
- ADDED «Збереження версії»: збереження створює версію 1 для нового шаблону чи наступну для наявного й робить її
  поточною (AC-EDITOR-03).
- ADDED «Версія без обов'язкової задачі»: версія не створюється, повідомлення «A template needs at least one required
  task» (AC-EDITOR-04).
- ADDED «Список версій»: номер, дата й час, email автора, від новішої (AC-EDITOR-05).
- ADDED «Версія запуску»: запуск показує «Template version N» і задачі своєї версії (AC-EDITOR-06).
- ADDED «Список версій лише для адміністратора»: менеджер бачить «Not enough rights» (AC-EDITOR-07).
- ADDED «Зміна шаблону лише адміністратором»: прямий запит менеджера нічого не змінює (AC-EDITOR-08).
- ADDED «Редактор без входу»: відвідувач бачить сторінку входу (AC-EDITOR-09).

`ui-consistency` (нова можливість):

- ADDED «Однакові статуси запуску»: ті самі слова й кольори, слово поруч із кольором (AC-DSYS-01).
- ADDED «Відмова в правах на сторінці»: «Not enough rights» і «Back to templates» у спільному макеті (AC-DSYS-02).
- ADDED «Сторінка входу для відвідувача без входу»: у спільному макеті, без даних запуску (AC-DSYS-03).
- ADDED «Порожній список запусків»: «No runs yet. Launch a template to start one.» і «Launch a template» (AC-DSYS-04).

Специфікації першого зрізу (`run-launch`, `run-progress`) не змінюються: у вимозі «Launch a template for a case» PM
змінив лише «Поза межами» й «Припущення» (рядок журналу змін 2026-10-25), AC ті самі.

## Capabilities

### New Capabilities

- `template-editor`: редагування шаблону адміністратором, незбережені зміни, збереження пронумерованої версії, список
  версій, версія запуску й відмови для менеджера та відвідувача без входу.
- `ui-consistency`: єдиний вигляд і поведінка сторінок — статуси, відмови в доступі, сторінка входу й порожні стани.

## Users & roles

Ролі — з матриці прав `requirements/product.md` і розділів «Користувачі й ролі» вимог #19 і #20. Терміни глосарію PM:
незбережені зміни = Unpublished changes, версія = Version, поточна версія = Current version, редактор = Editor,
дизайн-система = Design system.

| Роль | Дія зрізу 2 | Межа |
|---|---|---|
| `admin` | бачить шаблони | усі, зокрема з незбереженими змінами |
| `admin` | створює шаблон, редагує секції й задачі, зберігає нову версію | будь-який шаблон |
| `admin` | бачить список версій шаблону | будь-якого шаблону |
| `admin` | бачить версію запуску | у всіх запусках |
| `manager` | бачить шаблони | лише збережені як версія і лише поточну версію |
| `manager` | створює, редагує шаблон, зберігає версію | —, бо шаблони налаштовує лише адміністратор |
| `manager` | бачить список версій | —, бо менеджер працює лише з поточною версією |
| `manager` | бачить версію запуску | у запусках, які він бачить |
| не увійшов | будь-яка сторінка | лише сторінка входу, бо застосунок внутрішній |

Рішення про ролі (PM, «Продукт»): ролі призначає й змінює лише адміністратор і лише іншому користувачу; власну роль не
змінює ніхто; останній адміністратор роль не втрачає; менеджер не змінює нічиєї ролі. Екрана керування ролями в зрізі
немає.

## Non-goals

З розділів «Поза межами» вимог #20 і #19:

- Поля в задачах, змінні запуску, умови, правила призначення й терміни в редакторі — пізніші зрізи; редактор зрізу 2
  працює лише із секціями, задачами й позначкою «required» / «optional».
- Видалення й виведення шаблону з ужитку.
- Перегляд старішої версії, порівняння двох версій і відновлення старішої версії.
- Одночасне редагування одного шаблону двома адміністраторами.
- Погодження нової версії іншою людиною: адміністратор, який зберігає версію, її й публікує.
- Імпорт шаблонів із файлу.
- Темна тема, інші мови інтерфейсу й окремий вигляд для конкретного клієнта (вимога #19).
- Сторінки, яких ще немає; анімації й ілюстрації.
- Яку дизайн-систему використати і як її побудувати — вирішує розробник.

## Assumptions

Припущення PM (вимоги #20, #19, #2):

- Користувачів із ролями `manager` і `admin` створює адміністратор і обирає роль у момент створення; у навчальному
  проєкті — як початкові дані. Користувача без ролі не існує.
- Шаблони змінюють лише адміністратори; кожен адміністратор може змінити будь-який шаблон.
- Зміни зберігаються автоматично під час редагування, а збереження шаблону створює версію. У шаблону одночасно один
  набір незбережених змін, спільний для всіх адміністраторів: хто відкриває редактор, продовжує з нього.
- Незбережені зміни — не версія, їх немає в списку версій і їх ніколи не показують менеджерам.
- Номери версій — цілі числа 1, 2, 3… в порядку збереження; номер ніколи не використовується повторно, а збережена
  версія ніколи не змінюється.
- Збережена версія стає поточною для всіх наступних запусків; уже запущений запуск зберігає версію, з якої його
  запущено. Зміна шаблону — це збереження нової версії, вона ніколи не зачіпає вже запущений запуск.
- Новий шаблон, ще ніколи не збережений як версія, адміністраторам показано з «Unpublished changes», а менеджерам — не
  показано.
- Версію запуску показано як «Template version N» на сторінці запуску.
- Список версій показує лише номер, дату й час збереження та email адміністратора; дати й час — за київським часом,
  у формі DD.MM.YYYY HH:MM, до хвилини.
- Назви секцій і задач — вільний текст; обмежень довжини в зрізі немає.
- Інтерфейс англійською: повідомлення й статуси — дослівно як в AC і глосарії.
- Сторінки, яких стосується вимога #19: вхід, список шаблонів, редактор, список версій, форма запуску, список
  запусків і сторінка запуску. Тон, кольори за змістом, щільність і стиль текстів — з «Вигляд і тон» у «Продукті».
- Усі дати й час у застосунку — за київським часом (вимога #19).
- Дані навчальні: назви об'єктів і користувачі вигадані (`*@example.test`).

Робочі припущення розробника (до відповіді PM; журнал — `docs/spec-reading.md`, розділ «Зріз 2»):

- (розробник) Шаблони «Tenant move-in» і «Apartment repair», підготовлені як початкові дані зрізу 1, стають версією 1;
  запуски зрізу 1 показують «Template version 1».
- (розробник) Умовні задачі — зріз WS9 за roadmap «Продукту»: у зрізі 2 кожна задача збереженої версії копіюється в
  кожен запуск (суперечність зі «slice WS7» у вимозі #2 — питання до PM).
- (розробник) Шаблон без жодної збереженої версії не запускає ніхто, зокрема адміністратор: за глосарієм PM запуск
  ніколи не створюється з незбережених змін («a run is never launched from them»); остаточно — питання колеги
  solomchaak/property-workflows-spec#21.
- (розробник) Збереження без незбережених змін нової версії не створює (питання колеги
  solomchaak/property-workflows-spec#22).
