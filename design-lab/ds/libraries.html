Яка бібліотека компонентів — і чому не лише shadcn

Усі версії, дати, ліцензії й стан підтримки нижче звірені з npm registry, GitHub API та офіційними доками на 23 жовтня 2026. Розміри бандлів — наші власні вимірювання esbuild (minify + gzip). Що не вдалося перевірити — позначено явно.

Короткий висновок. Тримаємо правило курсу (код — у src/components/ui, тема — CSS-токени), але замість «усе на Base UI» беремо React Aria Components як ядро (~85% контролів, включно з єдиними у класі DatePicker/TimeField з часовими поясами, NumberField з валютою, доступним DnD) і Base UI лише для Toast. Доставка — shadcn CLI 4.2x (--base aria) плюс власні компоненти поверх RAC.

  • Ядроreact-aria-components 1.22.1 + @internationalized/date 3.12.4
  • Toast@base-ui/react 1.9.0 (лише Toast; запасний — Sonner)

  • ⌘KRAC Autocomplete у Modal (запасний cmdk)

  • РухCSS linear()-пружини з токенів + <ViewTransition> + Motion (лише layout)
Рекомендовано

A · «React Aria-first» гібрид

RAC для форм, оверлеїв, даних, date/time, DnD. Base UI — лише Toast. Оболонка — shadcn aria-база.

Плюси
  • Єдині серед усіх: DatePicker, DateRangePicker, TimeField із ZonedDateTime
  • Фокус-менеджмент в одній системі (мінімум конфліктів)
  • DnD, Tree, Table, DropZone з клавіатурою та screen reader
  • Щомісячні релізи, MCP + agent skills
Мінуси
  • Бандл важчий за Base UI (Select 57 vs 44 kB gz)
  • shadcn aria-база молода (07.2026), без DatePicker/NumberField — пишемо самі
  • Toast/TokenField ще нестабільні в RAC
Альтернатива B

B · «Base UI + shadcn» (дефолт курсу)

npx shadcn init (base-nova), RAC лише «островами»: date/time, DnD, Tree, NumberField.

Плюси
  • Найзріліший реєстр і документація; менший бандл
  • Найкращі data-starting/ending-style для spring-анімацій
Мінуси
  • Дві системи фокусу в кожному діалозі з датою
  • Календар лише react-day-picker (без ZonedDateTime/TimeField)
  • Два набори атрибутів стану → більше glue-коду
Альтернатива C

C · «Тільки React Aria»

Без Base UI взагалі: Toast — Sonner або RAC UNSTABLE_Toast.

Плюси
  • Одна бібліотека, один набір data-* станів
  • Простіше навчати команду й агентів
Мінуси
  • Toast: нестабільний API або сторонній Sonner (a11y гірше задокументована)
  • Немає запасного Drawer (RAC Sheet — 2 тижні від релізу)
СторінкиЛише семантичні утиліти Tailwind з токенів (bg-card, text-muted-foreground); CI-скрипт банить hex і zinc-500 поза src/components/ui.
src/components/uiНаш код: обгортки RAC/Base UI, одна фокус-обводка, спільні @custom-variant (selected · open · pressed · invalid · entering · exiting).
ПримітивиRAC (форми, оверлеї, дані, date/time, DnD) · Base UI (Toast) · xyflow · Tiptap — без власних стилів.
CSS-токениtokens.css → @theme inline: OKLCH, shadcn-імена, --status-*, --ai, --spring-*; темна тема лише через prefers-color-scheme.

П’ять найнесподіваніших знахідок

Те, що змінило рекомендацію порівняно з «очевидним» вибором.

  1. Найпопулярніший реєстр на Base UI — coss ui — під AGPL-3.0.

    Peer-залежності next ^16.4 · react ^19.3 · tailwind ≥4.3 збігаються з нашим стеком, 56 компонентів — але packages/ui має ліцензію AGPL-3.0-or-later; MIT лише у apps/ui (сайт документації). Копіювати в закритий SaaS без юриста не можна. LICENSING.md coss.com/ui

  2. shadcn вже має третю базу — React Aria (--base aria, липень 2026).

    І це сам по собі гібрид: aria-drawer імпортує Base UI Drawer, toast — Sonner, а DatePicker/TimeField/NumberField/Toast у реєстрі немає взагалі. changelog реєстр aria

  3. Base UI 1.9 досі не має Calendar/DatePicker.

    У пакеті лише internal temporal-adapter-date-fns/luxon — тобто календар готується, але не публічний. Для вимоги «Europe/Kyiv date/time/range» це вирішальний аргумент на користь RAC. список компонентів

  4. RAC має TokenField (alpha), Sheet і NavigationTree — але Toast усе ще UNSTABLE_.

    TokenField (1.20, липень) — інлайн-чипи в текстовому полі: прямий кандидат для {{змінних}}. Sheet з’явився 09.10.2026. Toast від Adobe лишається нестабільним, тому Toast беремо з Base UI. TokenField v1.22

  5. «Стандартні» залежності тихо завмерли.

    cmdk — жодного релізу в 2026 (останній 14.03.2025); Vaul — «unmaintained» у README; Headless UI — один реліз за рік; Radix — на npm без релізів січень–травень і серпень–вересень; Tremor — заморожений на React 18. Водночас нові мажори летять швидко: TanStack Table 9 (08.2026), Pragmatic DnD v2→v4 за 3 місяці, Motion 13→14 за 2 місяці. Vaul README cmdk

Матриця оцінок

Оцінки 1–5 — наш висновок за перевіреними фактами (рядок «чому» і посилання в кожному). «Правило курсу» = можна вендорити в src/components/ui і тема живе в CSS-токенах. Сума — лише орієнтир, не вердикт: Base UI програє через відсутність date/time, хоча в усьому іншому не гірший.

Хто виграє для кожного контролу

«RAC» = react-aria-components. Усі контроли стилізуються нами в src/components/ui; жоден не рендерить дефолтний вигляд браузера (нативні <select>/input[type=date] лише приховані для форм).

Toasts: Sonner · Base UI · RAC

Вибір Base UI Toast

Sonner 2.0.8 (09.08.2026) живий і простий. Base UI Toast stable: undo через actionProps, стек через CSS-змінні (--toast-index, --toast-swipe-movement-*), limit. shadcn додав власний Toast на Base UI (07.2026). RAC експортує лише UNSTABLE_Toast*.

shadcn toast · sonner

Drawer / Sheet: Vaul · Base UI · RAC

Вибір RAC Sheet; запасний — Base UI Drawer

Vaul 1.1.2 (12.2024), у README: «This repo is unmaintained». Base UI Drawer: preview у 1.2.0 (12.02.2026), stable в 1.3.0, у 1.9 — багато правок iOS/клавіатури. RAC Sheet з’явився 09.10.2026 — гарний, але 2 тижні від релізу.

vaul README · RAC 1.22

Дата/час із часовими поясами

Вибір RAC + @internationalized/date

ZonedDateTime у Europe/Kyiv, DatePicker/DateRangePicker/TimeField, hourCycle, hideTimeZone. У БД — timestamptz (UTC), у UI — toZoned(…, 'Europe/Kyiv'). react-day-picker 10.0.2 (09.2026) — лише календар (потрібен @date-fns/tz); пакет перейменовано на @daypicker/react у v10. Base UI календаря не має.

RAC DatePicker · DayPicker v10

Рух: Motion · ViewTransition · CSS linear() · AutoAnimate

Вибір CSS-пружини з tokens.css + ViewTransition + Motion лише для layout

React 19.3 має (локальні доки Next 16.4: «React 19.3 includes the ViewTransition component»), анімації запускають Transition/Suspense/useDeferredValue. 90% руху — вже в токенах (--spring-* на linear()). Motion 14.x (m + LazyMotion ≈29 kB gz) — для layoutId/FLIP тостів і табів; Reorder у 14.6.0 отримав клавіатурне перевпорядкування. AutoAnimate 0.10 — для тривіальних списків.

Next view-transitions (локально) · Motion changelog

DnD: dnd-kit · Pragmatic · RAC

Вибір RAC DnD для списків/дерев

Класичний @dnd-kit/core 6.3.1 не оновлювався з 12.2024; нова лінійка @dnd-kit/react 0.5.1 (15.10.2026) ще 0.x. Pragmatic DnD (Atlassian, Apache-2.0) швидкий (≈7 kB gz), але a11y треба будувати самому, і за 4 місяці вийшли мажори 2→3→4. RAC DnD має клавіатуру й screen reader з коробки.

Доставка коду

  1. npx shadcn@latest init --base aria — отримуємо aria-версії button, input, select, dialog, sheet, tabs, tooltip, popover, context-menu, command, combobox, slider, switch, table, sidebar тощо (≈55 файлів у реєстрі). Токени — ті самі shadcn-імена, що в tokens.css.
  2. Заборонити native-select і sonner (aria-база) — лінтер/CI; toast.tsx беремо з Base UI-бази реєстру (apps/v4/registry/bases/base/ui/toast.tsx); чи CLI 4.21 дозволяє змішувати бази — перевірити в пілоті, інакше копіюємо файл вручну.
  3. Власні файли за документацією RAC (Tailwind-приклади; ліцензію starter-kit звірити перед копіюванням): date-picker.tsx, date-range-picker.tsx, time-field.tsx, number-field.tsx, tag-group.tsx, drop-zone.tsx, tree.tsx.
  4. Сторонні реєстри (React Flow UI) — через npx shadcn add https://ui.reactflow.dev/…; у components.json прописати registries. Приватний GitHub-реєстр теж підтримується (08.2026).
  5. Піни точних версій; оновлення — через ADR (правило шаблону).

Один вигляд поверх двох шарів (Tailwind 4)

/* globals.css — єдиний словник станів */
@custom-variant selected (&:is([data-selected],[aria-selected="true"],[data-checked],[aria-checked="true"]));
@custom-variant open     (&:is([data-open],[data-state="open"],[aria-expanded="true"],[data-popup-open]));
@custom-variant pressed  (&:is([data-pressed],[aria-pressed="true"]));
@custom-variant invalid  (&:is([data-invalid],[aria-invalid="true"]));
@custom-variant entering (&:is([data-entering],[data-starting-style]));
@custom-variant exiting  (&:is([data-exiting],[data-ending-style]));

@utility focus-ring {          /* та сама обводка з base.css */
  &:is(:focus-visible,[data-focus-visible]) {
    outline: var(--ring-width) solid var(--ring);
    outline-offset: var(--ring-offset);
  }
}
@utility pop-in  { animation: pw-pop  var(--spring-snappy-duration) var(--spring-snappy) both; }
@utility pop-out { animation: pw-exit calc(var(--duration-base) * var(--exit-factor)) var(--ease-exit) both; }
  • Приклад поповера: entering:pop-in exiting:pop-out — той самий клас для RAC і Base UI.
  • Рух: пружини — це linear() у токенах; reduced-motion вже стискає відстані в tokens.css. Motion підключаємо лише через LazyMotion.
  • Шари: усі z-index з --z-*; корінь застосунку isolation:isolate.
  • Тема: жодного .dark; лише prefers-color-scheme у токенах — компоненти нічого про тему не знають.
  • Правило CI: курс дозволяє hex лише в src/components/ui і globals.css; ми йдемо суворіше (BRIEF §2): і там лише var(--token) та color-mix() від токенів.
Divergence від BRIEF §7: бриф вимагає <dialog> + showModal(); RAC Modal — div role="dialog" із власною фокус-пасткою (ARIA-поведінка еквівалентна, але top layer браузера не використовується). Потрібне рішення власника — див. «Питання».
