01 · Overview

Overlays & feedback

Everything that floats above the page or answers an action: buttons that wait without jumping, dialogs that ask once, menus that grow from their trigger, a ⌘K palette, toasts that can be undone, and calm empty and error states. Quiet depth, no theatre.

02 · Buttons

Button system

Six variants, three sizes, icon-only and a loading state that holds its width: the icon morphs into a spinner and the label into its progressive form. Press is a 0.98 scale on a snappy spring. Destructive red is reserved for destructive actions — the last-task confirmation is a primary action.

Keyboard & ARIA

  • Enter / Space activate; icon-only buttons need aria-label.
  • Loading: aria-busy="true", button stays focusable and the label becomes the progressive form (“Marking…”).
  • Disabled that must stay reachable uses aria-disabled="true" plus a tooltip that says why.
  • Targets 28 / 32 / 36 px — all ≥ 24 px (WCAG 2.5.8).

03 · Dialog

Dialog and alert dialog

A native <dialog> opened with showModal(): focus is trapped, the page behind is inert, Esc exits and focus returns to the trigger. The overlay fades in with a soft 4px blur; the opaque panel rises on a smooth spring and leaves faster.

Keyboard & ARIA

  • Confirmation: role="dialog", focus lands on the first action (Cancel); ⌘↵ confirms from anywhere inside.
  • Destructive: role="alertdialog", focus on Cancel; the destructive button stays aria-disabled until the name is typed exactly.
  • Clicking the backdrop dismisses a dialog; an alert dialog only nudges, so a stray click never discards intent.
  • Title and description are wired with aria-labelledby / aria-describedby.

Tokens

--surface-3--overlay--overlay-blur--shadow-lg--radius-xl--spring-smooth--exit-factor--scale-enter--size-dialog-sm--size-dialog--destructive-tint
04 · Popover and tooltip

Popover and tooltip

Popovers are glass, grow from the side of their trigger and carry an optional arrow. Tooltips are small and crisp: the first waits 500ms, then neighbouring triggers show theirs instantly for a moment — so sweeping across a toolbar feels continuous.

Keyboard & ARIA

  • Popover: trigger has aria-expanded + aria-controls; panel is a non-modal role="dialog"; Esc closes and returns focus.
  • Tooltip: role="tooltip" linked by aria-describedby, on hover and focus, Esc hides, never holds essential information.
  • Placement flips at the viewport edge; transform-origin follows the trigger centre.

Tokens

--glass-bg--glass-blur--glass-border--shadow-md--z-popover--z-tooltip--spring-snappy--tooltip--tooltip-delay--tooltip-skip--size-popover--size-arrow
05 · Menu

Dropdown menu

Sections, icons, shortcuts, checkable items, a submenu and one destructive item. The menu grows from the trigger, items arrive 12ms apart, and the highlight follows pointer and keyboard as one cursor.

Keyboard & ARIA

  • Button: aria-haspopup="menu"; ↓ / Enter open on the first item, ↑ on the last.
  • ↑↓ move, Home/End jump, typing jumps to a label, → opens a submenu, ← / Esc close it.
  • menuitemcheckbox and menuitemradio carry aria-checked; checkboxes keep the menu open.
  • Pointer open hides the focus ring (data-pointer); any key brings it back.

Tokens

--glass-bg--radius-md--size-control-sm--stagger--destructive--accent-float--size-menu--submenu-delay--destructive-tint
06 · Command palette

Command palette

The one modal allowed to be glass. Search runs, templates and actions together; matches are underlined, the selected row shows its default key, and a second ⌘K opens actions for the selected item. Both panels below are fully interactive — and so is the real one on ⌘K.

Keyboard & ARIA

  • ⌘K / CtrlK opens; dialog + combobox + listbox, focus stays in the input (aria-activedescendant).
  • ↑↓ move, ↵ runs the default action, ⌘K again toggles the action panel, Esc closes it first, then the palette.
  • Groups are role="group" labelled by their heading; the status line announces “No results”.
  • Loading shows a hairline progress and skeleton rows with aria-busy.

Tokens

--glass-*--radius-lg--shadow-lg--overlay-blur--spring-smooth--shimmer-duration--size-palette--overlay-palette--accent-float--indeterminate-duration
07 · Toasts

Toasts

Bottom-right, glass, never stealing focus. Up to three: older ones tuck behind the newest as a deck and fan out when you hover. The stack reflows on a smooth spring; hover or focus pauses the timer; drag sideways to dismiss. Fire them from the buttons — they appear in the corner of your window.

Keyboard & ARIA

  • Container is role="region" “Notifications”; each toast is role="status" (polite), errors role="alert".
  • Never moves focus. Undo and Dismiss are real buttons, reachable by Tab; focus inside the stack pauses timers like hover.
  • Undo toasts carry a 5s countdown line; success and info last 4.5s, errors 8s.
  • Reduced motion: stack positions apply as short fades, no sideways travel.

Tokens

--glass-*--shadow-md--z-toast--spring-smooth--distance-3--status-done--toast-duration--toast-peek--toast-peek-scale--swipe-threshold--size-toast
08 · Alerts and banners

Inline alerts and banners

Feedback that lives with the content. Tint from the status roles, an icon that doesn’t depend on color, and text on the tint at ≥ 4.5:1. Errors say what happened and what to do — no apologies, no “Oops”.

Keyboard & ARIA

  • Static information: role="status". Errors that appear after an action: role="alert" and the field that failed gets focus.
  • Dismiss is an icon button with aria-label; dismissed alerts exit at 0.7× and the layout closes up.
  • “Run not found” does not reveal whether the run exists.

Tokens

--status-progress-*--status-due-soon-*--status-overdue-*--status-done-*--radius-md--muted
09 · Loading

Skeletons, progress and optimistic updates

Skeletons shimmer with a slow sheen, then the content arrives with a light stagger. Progress fills on a spring or breathes when indeterminate. Optimistic updates change the UI instantly and say so honestly if the server disagrees.

Keyboard & ARIA

  • Skeleton containers: aria-busy="true" and a visually hidden “Loading…”; shimmer stops under reduced motion.
  • Progress bars use role="progressbar" with aria-valuenow, or omit the value when indeterminate.
  • Optimistic checkbox: role="checkbox"; a failed save reverts the state, flashes the row and raises an error toast with a way back.

Tokens

--skeleton--skeleton-sheen--shimmer-duration--stagger--status-progress--status-done--spinner-duration--indeterminate-duration
10 · Empty states

Empty states

What will be here, in one sentence, and one action. Line illustrations are built from tokens, so they re-tint with the theme; the single accent stroke marks the thing to do.

Keyboard & ARIA

  • Title is a real heading; the illustration is aria-hidden.
  • One primary action only; permission states offer a way out, never a dead end.

11 · Sheet

Sheet for task details

On narrow widths the task details move from the third zone into a right-hand sheet. It is modal, so it behaves like a dialog: inert page, Esc, return focus. It travels only 24px — a hint of direction, not a slide-show.

Keyboard & ARIA

  • Native <dialog> modal, aria-labelledby the task title; focus starts on Close.
  • Backdrop click and Esc close; the exit is 0.7× the enter.
  • At 390px the sheet fills the width minus a 24px peek of the page.

Tokens

--surface-3--radius-xl--shadow-lg--ease-emphasized--size-sheet--distance-sheet
